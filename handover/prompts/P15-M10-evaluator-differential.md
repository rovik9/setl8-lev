WHAT THE REFERENCE EVALUATOR IS
The evaluator is the trusted backend of DESIGN 1.3 and 4.3 written as a library: it owns the order book of the venue (market, limit, stop, close, cancel, set SL/TP orders, flips), values accounts on every sample, applies the rules with the engine, and emits (a) journal batches in the exact on-chain format, (b) the sample archive, (c) the intents file, (d) the pass and fail calls the program needs. It is also the reference for any production backend: a backend in another language must reproduce its outputs bit for bit (golden vectors below). It is NOT a networked service; there is no RPC code here.

SCOPE
1. `crates/evaluator` public API (design the types, document them): `Evaluator::new(rules, markets, account params)`, `on_sample(market, source_ts, mid_e12 or quantized, receive_ts)`, `on_order(signed intent)`, `tick(now)` (rollover fees, closed markets, pending orders), and `drain_batches(policy) -> Vec<Batch>` where `Batch` is the `JournalBatch` bytes plus the proofs, the Meta (samples_hash, intents_hash from the real prefix hashes, engine_version, flat), the archive bytes and intents lines committed so far. Batching policy: at most 8 events and 3 proofs, `Meta` last in every batch, and a SPLIT rule so that the signed transaction never exceeds 1,232 bytes and 200k compute units (measure both in tests; the transaction is the real `post_journal` instruction with its real account list).
