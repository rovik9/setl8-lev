# Module M9: the public verifier `setl8-verify` (DONE, verified 2026-10-12)

Crate `crates/verifier` (package `setl8-lev-verifier`, library `setl8_verify` + binary `setl8-verify`), in the root workspace. Formats and the evaluator conventions it assumes: `handover/verifier-formats.md`. Two commits: stage 1 (formats, chain, event replay, intents) and stage 2 (archive walk, second recorder, pass verdicts, `watch`). The program, tests-rs, engine and journal-types were NOT touched. Dependencies (CLI shell and parsing only): `serde`, `serde_json`, `bs58`, `sha2`, `ed25519-dalek 1.0` (the only version in the offline registry); `proptest` for tests. The replay core is pure (no I/O, no clock).

## CLI
```
setl8-verify account --events E.jsonl --rules R.json --archive A.bin --intents I.jsonl [--snapshot S.json] [--second-archive B.bin] [--json] [--as-of-seq N]
setl8-verify watch   --events E.jsonl --rules R.json --archive A.bin --intents I.jsonl [--second-archive B.bin]
```
Exit codes: 0 valid, 1 mismatch, 2 input error (missing file, wrong format, bad arguments). Human text by default (`VERDICT`, the replayed state, one line per finding, per-phase and per-pass lines), stable JSON with `--json` (fields in declaration order, findings sorted by (seq, event index, class, message); no timestamps). `--as-of-seq N` replays only the events up to sequence N (the watchdog use of DESIGN 4.6). `watch` prints one line for the newest pending pass: `VALID seq=N`, `MISMATCH seq=N classes=A,B` or `NO_PENDING_PASS` (a pass is pending until it is rejected, vetoed, finalized or ended by a fail); no network.

## Library
`verify_account(&Inputs) -> Result<Report, InputError>`; `Report { verdict: Valid | Mismatch, findings (at most 1,000, then `truncated`), per_phase: [PhaseVerdict], per_pass: [PassVerdict], state: StateSummary }`; `Finding { class, seq, event_index, expected, found, message, source }`. The replay (`replay.rs`) rebuilds positions and the `AccountState` event by event with `engine::apply_fill`, `check_close`, `apply_closed_slice`, `check_tight_start`/`check_floor_raised`/`check_breach`/`check_tight_end`, the cost functions and `engine::claims` prices; `walk.rs` is the stage-2 archive walk.

## Finding classes
| class | meaning |
|---|---|
| HashChain | the replayed chain head differs from the stored `journal_hash` |
| SequenceGap | an event line's sequence is not the previous + 1 (dropped, repeated, reordered), or the stored account is at another sequence |
| BadGenesis | `opened.genesis_hash` is not `sha256("SL8LEV" ++ account)` |
| EventDecode | event or proof bytes do not decode, or the engine refuses the event |
| UnknownEvent | a log line of an unknown `type` |
| ProofFeed | the proof's feed is not the market's feed (or belongs to no market) |
| ProofAge | the proof is outside `event time - max_age ..= event time + 2` |
| ProofShape | `signed_update` shape wrong for the source, bad value, a proof missing where required or present where not referenced |
| PriceMismatch | the event price differs from the proof mid with the half-spread (`engine::claims`) |
| ArchiveMissing | a proof is not a record of the archive (market, source, timestamp, value, digest) or lies outside the batch's committed prefix; no mark for a holding fee |
| SamplesHashMismatch | `Meta.samples_hash` matches no record boundary, or the committed prefix shrank |
| IntentsHashMismatch | same for `intents_hash` and line boundaries |
| ForgedTrade | no matching signed intent (absent, other market/side/kind/levels/quantity, dated after the trade, outside the committed prefix, wrong origin for the close reason) |
| BadIntentSignature | the ed25519 signature is not the trader's over `SL8LEV | account | nonce | order` |
| IntentDecode | an intent line is unusable (not JSON, bad hex, bad order bytes, nonce 0, duplicate nonce) |
| UnknownMarket | the event names a market the rules do not list |
| PositionMismatch | Close without a position, on the other side, or larger than the position; a Fill that reduces |
| PnlMismatch / CreditMismatch / QuickMismatch | `check_close` against the REPLAYED position (timer and quick flag included) |
| FeeMismatch | holding or commission fee wrong, missing, unexpected (flat day, wrong time or market) or too many nights between two events to check |
| MarginMismatch | `Fill.margin` is not the margin of the whole position |
| AvgEntryMismatch | `avg_entry_after` or a Close's `entry_e12` differs from the replayed average |
| FloorMismatch | TightStart/FloorRaised/Breach/TightEnd claims fail the engine formulas; breach with open positions; missing TightEnd |
| StateMismatch | snapshot field differs; `Meta.flat` disagrees; time goes backwards; events after the account ended; second `opened`; log ends inside a batch |
| EngineVersion | `Meta.engine_version` is not the engine's |
| PassInvalid | a pass request/confirmation or a phase change that the replay does not support (reasons in `per_pass`) |
| FalseFail | a `Fail` the replayed state does not justify |
| MissedBreach / MissedFail / MissedTightStart / MissedFloorRaise | the samples require it, the journal has none |
| FalseBreach / FalseTightStart / FalseFloorRaise | the journal has it, the samples do not support it |
| WrongLLevel | formula-consistent TightStart/FloorRaised whose `p_open`/`g_peak`/`l_level` differ from the samples' |
| TriggerMissed / TriggerFalse | a stop-loss, take-profit, limit or stop the samples trigger and the journal lacks / the journal has and no sample triggers. M9b: a limit or stop is executed by a `Fill` of its kind OR a `Close` (Manual/Flip) under its nonce; a pending order whose margin check fails is not expected to execute |
| ArchiveDisagreement | the two archives differ at the same market and source timestamp |
| PendingFillWithoutMargin | (M9b, D3) a pending order was executed although the account could not margin it at its trigger sample (`b + P - commissions` below the margin of the positions it would leave) |
| FillWithoutMargin | (M9c, B1) a MARKET order was executed although the account could not margin it (the same formula; the order's own sample is its market's mark) |
| FillNotAllowed | (M9c, B2) an execution the evaluator's own rules refuse and the verifier can reproduce: the account is held, the breach lock, a market that is disabled or reduce-only, a quantity off the step or below the minimum, a ninth position, a position above the notional cap, or a closed market. The message names the reason. A triggered PENDING order refused for one of them is expected not to fill, and its fill is this finding (margin: `PendingFillWithoutMargin`) |
Classes added to the prompt's list: `ProofShape`, `IntentDecode`, `UnknownMarket`, `PositionMismatch`, `PassInvalid`, `FalseFail`, `FalseBreach`-family (`FalseTightStart`, `FalseFloorRaise`).

## M9b (decisions D1 to D5, handover/design-decisions.md 53)
The verifier was aligned with the five findings M10 reported (handover/module-10.md "Findings"); what changed, exactly:
* **D1** `walk.rs`: `walk_close(ctx, market, reason, intent, qty)` takes a `Manual`/`Flip` close under the nonce of a pending order of its market as that order's execution (`consume_pending`), a `Flip` close marks its `Fill` as the other half (`flip_open`). New unit tests in `walk.rs`, vectors `d1_*` and `tests/m9b.rs::d1_*`.
* **D2** `replay.rs::on_close`: no commission expectation after the slice whose `apply_closed_slice` says the quick limit is exceeded, and the quantity total of its intent is no longer required (`nonce_qty[intent].1 = None`). `m9b.rs::d2_*`.
* **D3** `walk.rs`: the pending orders a second triggers are collected (`Walker::cand`) and judged when the second is complete (`resolve_second`): the second's stop-loss and take-profit closes are simulated first, then each order by (market, nonce) is netted and margin-checked with the evaluator's formula (`sim_pending`, `profit_for` with the trigger sample as the order's market mark); a failing order is recorded (`Walker::refused`) and no event is expected, a passing one becomes the usual `Pending` expectation. New class `PendingFillWithoutMargin` (declared LAST in `FindingClass`, so the sort order of every other class is unchanged; also in the second recorder's walk classes). `margin_tests` (12 unit tests with hand-computed numbers), `m9b.rs::d3_*`.
* **D4** `walk.rs::breach_shape`: a `Breach` expectation becomes `Fail(StaticFloor)` / `Fail(PhaseQuick)` when the engine-booked forced closes end at or below the static floor / over the quick limit. `m9b.rs::d4_*`. Order of checks: the static floor is named first, as in `check_breach` (`engine/src/claims.rs`: balance, then not-below-floor, then `BreachBelowStaticFloor`); in the program the quick overshoot is caught earlier, at the `Close` (`QuickLimitExceeded`), and `report_fail` accepts either reason when both hold (`post_journal.rs apply_fail`: StaticFloor needs `b <= floor`, PhaseQuick needs the tally over), so the walk's `Fail` expectation is matched whatever the reason and the posted reason is judged by `on_fail` against the replayed state.
* **D5** `verify.rs::drive`: a `phase_advanced` directly after a `pass_finalized` with the same new phase is a no-op; any other needs an unresolved `pass_requested` of its `from_phase` (new `StateMismatch` otherwise). `m9b.rs::d5_*`.
Conventions 4, 6, 9, 11 and 12 above carry the M9b changes.

## M9c (decision 59): the evaluator's own refusals, recomputed
What changed, exactly (formats and semantics: verifier-formats.md section 9):
* **`walk.rs::open_refusal`** is the one function for every exposure-increasing execution: held, lock, market status, quantity, position count, notional cap, margin, in the evaluator's order, returning a `Refusal`. `sim_pending` (triggered pending orders, D3) calls it with `Check::PENDING`; `check_market_order` (market orders) with `Check::MARKET`. `Sim::Refused(Refusal)`; `Walker::refused` and `consume_pending` carry the reason, so a refused pending order that is executed anyway is `PendingFillWithoutMargin` (margin) or `FillNotAllowed` (the rest).
* **`walk.rs::check_market_order` / `check_market_close`**, called from `replay.rs::on_fill` (a `Fill` of kind Market) and `on_close` (the `Close{Flip}` of a market order, judged as a whole before its closing slice; a `Close{Manual}` under a market or close intent): the market must be open (`Walker::lc_at` records the market's last-change second as of every walked sample; the order's sample is the proof's, remembered in `Replay::last_proof_si`), the quantity named must be on the step, and `open_refusal` must find nothing. The `Fill` that is the other half of a market flip is not judged again (`Replay::flip_checked`).
* **Holds.** `log.rs`: lines `account_held` / `hold_released`; `replay.rs::on_hold` keeps the intervals (a hold on a held account and a release of an account that is not held are `StateMismatch`), `held_at(sec)` is true from the second of the hold line up to (excluding) the second of the release line.
* **New classes** (declared last, so every other class keeps its place): `FillWithoutMargin`, `FillNotAllowed`; both are second-recorder walk classes (`verify.rs::WALK_CLASSES`).
* **Tests.** `src/walk.rs refusal_tests` (17, hand-computed numbers and the boundary of every check: exactly enough margin and one micro-USD short, the quantity at the minimum and one step under it, the cap and one step over it, the eighth and the ninth position, `lock_until` and one second before it, the session and the last-change second, the hold's first and last second), `tests/m9c.rs` (14, the whole pipeline: honest, nearest dishonest and boundary pairs, flips, caps under edited rules, holds with lines inserted at every boundary), `tests/m8.rs` (7, from M8).
* **A fix the new checks forced in the test generator, not in the verifier:** `tests/common/mod.rs::path()` meant to alternate a one-unit wobble between samples "so the price changes on every sample", but its test (`k % 2`) was never true for samples 10 s apart; the hand-written honest history therefore executed market orders in a market that decision 49 calls closed (a price that stood still for more than `max_age_secs`). The wobble now alternates per 10 s; no committed vector changed (the three vector sets do not use `path()`). `coverage.rs a_failed_phase_cannot_pass` bought 4.7 M EUR on $100,000 (margin $101,520): now 4.6 M EUR.
* **Conventions changed:** 12 (above) is superseded; 8 ("closed market: no floor, trigger or pending decision") now also applies to market orders: a market order executed while its market is closed is `FillNotAllowed`.

## P21 (decision 64): the verifier refuses an exposure increase in an unpriced market
* `Refusal::Unpriced` in `open_refusal` (walk.rs), in the evaluator's EXECUTION order: held, locked, not tradable, **unpriced**, quantity, ninth position, notional cap, margin. The check is `Rules::spread(market) == 0` (a market the rule set does not list reads as 0), after the `open_qty == 0` early return, so a close (or the closing slice of a flip) is never judged by it. Reason text: "an exposure increase in an unpriced market" (the finding's expected text is "no execution: ... is refused", `FillNotAllowed`).
* A market `Fill` (or the `Close{Flip}` that starts a flip) in an unpriced market is `FillNotAllowed`; a triggered pending order on file in an unpriced market is put in `refused` with `Refusal::Unpriced`: no fill is expected (no `TriggerMissed`), and a `Fill` of it is `FillNotAllowed` with the same reason. The same pending order in a PRICED market is expected to fill, so its absence is still `TriggerMissed`. No finding class changed number.
* Tests (`src/walk.rs refusal_tests`): `a_market_order_in_an_unpriced_market_is_a_fill_not_allowed_and_a_half_spread_of_one_is_not`, `a_close_in_an_unpriced_market_is_never_refused_but_the_opening_half_of_a_flip_is`, `the_unpriced_check_sits_after_the_status_and_before_the_quantity`, `a_triggered_pending_order_in_an_unpriced_market_is_expected_not_to_fill_and_a_fill_is_not_allowed`. The `margin_tests` and `refusal_tests` fixtures use a named `TEST_HALF_SPREAD_E6 = 1`; `P.spread` sets market 0's half-spread. `tests/m9c.rs` and the M9b vectors moved to a priced market (hand-recomputed boundaries, in the file); the vectors are the evaluator's output (`SL8_WRITE_VECTORS=1`).

## DESIGN edits
Two one-line notes (committed with stage 1): 4.5 (one logical record stream for all markets, prefix hashes found in one hashing pass, signed 48-byte `OrderIntent`s) and 4.6 (`setl8-verify account|watch`, exit codes).

## DECISIONS (design silent)
1. **Time model.** An event's `time` is the source second of the sample that caused it. The decision for a sample uses the account state BEFORE the first event of its second; an evaluator acts at most once per second and kind (the last sample's numbers are expected); intents are effective from the first sample STRICTLY after their `client_time`.
2. **`Meta.time` = the last sample the evaluator processed for the batch**; the walk runs to the largest event/Meta time, and to the `time` of a `pass_requested` line. A log that ends before a breach sample is not wrong until something later (a Meta, a pass request) shows the evaluator had seen that second.
3. **Holding fee**: one `Fee{Holding}` per night per position at the rollover instant 22:00:00 UTC (`time == R`), mark = bid (long) / ask (short) of the LAST sample of the market with second <= R, rate 0 means no fee. A fee dated R is applied before the samples of seconds >= R are judged. Missing fees are noticed at the first event dated after R, or at the end of the log. A gap of more than 3,660 nights between two events with positions open is reported, not walked.
4. **Commission**: a `Fee{Commission}` follows each Fill/Close of a class with a non-zero rate, amount `ceil(rate x margin_micro(qty, price, 1))`. **M9b (D2): except after the closing slice that pushes the quick tally over its limit** (the program allows only the `Fail` after it); a Fee there is a `FeeMismatch`.
5. **`Fill.margin` is the margin of the whole position after the fill**; `Fill.sl/tp` equal the intent's levels (non-zero replaces, zero keeps).
6. **Intent rules** (M9b D1: a Manual/Flip `Close` under the nonce of a pending order of its market is that order's execution; D2: the quantities under an intent whose closing slice overshot the quick limit are not required to add up): Manual/Flip closes and all Fills need an intent; StopLoss/TakeProfit/Breach/Fail closes must carry 0; kinds must match; quantities under one nonce add up to the intent's within one batch; intent lines after the last committed prefix are not judged; a line with a bad signature is reported once (no extra `ForgedTrade` for trades that cite it).
7. **Sample archive**: one stream for all markets; headers per segment, excluded from the hash; flags byte 0 distinguishes a record from a header; samples must be in non-decreasing source second across the stream (the walk stops at the first sample later than the target).
8. **Closed market**: no floor, trigger or pending decision on a sample of a closed market; its mark stays frozen for other markets' equity.
